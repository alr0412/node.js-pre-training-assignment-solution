STRATEGY FOR HANDLING UPSTREAM CHANGES
1. Fetch latest metadata from the company repository:
   git fetch upstream
2. Switch to the local integration branch:
   git checkout main
3. Merge upstream changes into local main (Fast-Forward):
   git merge upstream/main
4. Push updated main branch back to the personal fork:
   git push origin main
5. If working on a long-lived feature branch, integrate changes via:
   git checkout feat/task-8
   git rebase main

BEST PRACTICES FOR COMMIT MESSAGES
* Use Conventional Commits specification (e.g., feat:, fix:, chore:, docs:).
* Keep the subject line short and concise (under 50 characters).
* Use the imperative mood in the subject line (e.g., "add feature", not "added feature").
* Separate the subject from the body with a blank line if a detailed explanation is needed.
* Do not end the subject line with a period.
